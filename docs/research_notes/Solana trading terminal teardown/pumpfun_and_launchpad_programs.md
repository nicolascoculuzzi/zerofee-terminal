How this was researched: I downloaded the official pump.fun repo (docs + IDLs, last commit 2026-09-29) and the official npm SDKs (`@pump-fun/pump-sdk` 2.0.0, `@pump-fun/pump-swap-sdk` 1.20.0, Raydium, Meteora, Orca, Moonshot SDK tarballs), then cross-checked against **live mainnet state on 2026-10-03** (slot ~452,976,084): I decoded the `Global`, `FeeConfig`, PumpSwap `GlobalConfig` and pool accounts, plus real trade events, using the official SDK decoders. ## 1. pump.fun bonding-curve program: program ID, IDL, instructions, accounts/PDAs, and the 2025–2026 upgrades

### Takeaway
The pump bonding curve is `6EF8rrecthR5Dkzon8Nwu78hRvfCKubJ14M5uBEwF6P`. It has moved through about 10 interface changes since May 2025. Today the cleanest path is the **unified `buy_v2` / `sell_v2` / `buy_exact_quote_in_v2`** instructions (27/26 fixed accounts, no optional accounts, SOL and USDC pairs). The legacy `buy` / `sell` / `buy_exact_sol_in` still work, but since **2026-04-28** they need two extra trailing accounts: the `bonding-curve-v2` PDA and a buyback fee recipient. Always derive `creator_vault` from the **live** `bonding_curve.creator`, because fee sharing and holder rewards can change it.

**Upgrade timeline 2025–2026 (official repo docs and commit log) and what broke**
- 2025-04-04: docs published. `migrate` (to PumpSwap, permissionless) replaced the old `withdraw`-to-Raydium flow — [PUMP_PROGRAM_README](https://github.com/pump-fun/pump-public-docs/blob/main/docs/PUMP_PROGRAM_README.md); [commits](https://github.com/pump-fun/pump-public-docs/commits/main)
- **2025-05-12 11:00 UTC, creator fees (breaking, both programs).** Buy account index 10 (old unused `rent`) became `creator_vault`, and sell index 8 (old `associated_token_program`) became `creator_vault`. `BondingCurve` gained `creator` and needed `extend_account` when shorter than 150 bytes. PumpSwap pools needed extension to 300 bytes plus 2 new accounts (`coin_creator_vault_ata`, `coin_creator_vault_authority`) — [PUMP_CREATOR_FEE_README](https://github.com/pump-fun/pump-public-docs/blob/main/docs/PUMP_CREATOR_FEE_README.md); [PUMP_SWAP_CREATOR_FEE_README](https://github.com/pump-fun/pump-public-docs/blob/main/docs/PUMP_SWAP_CREATOR_FEE_README.md)
- 2025-07 to 2025-08: repeated IDL updates added `global_volume_accumulator` / `user_volume_accumulator` (PUMP token incentives; `track_volume` arg) — [commits](https://github.com/pump-fun/pump-public-docs/commits/main); account definitions in [idl/pump.json](https://github.com/pump-fun/pump-public-docs/blob/main/idl/pump.json)
- **2025-09-01 20:00 UTC, dynamic fees (breaking).** `fee_config` + `fee_program` became mandatory on buy/sell for both programs. Fees switched to market-cap tiers on bonding curves and *canonical* PumpSwap pools. The docs told integrators to widen slippage until their fee math matched — [FEE_PROGRAM_README](https://github.com/pump-fun/pump-public-docs/blob/main/docs/FEE_PROGRAM_README.md). (The brief calls this "Project Ascend"; that name does not appear in the official repo text I read.)
- 2025-11-07: `create_v2` (Token-2022 mints) and **mayhem mode**. 2025-11-15: "immutable global volume accumulator and reserved fee recipients", meaning mayhem coins must use the reserved fee-recipient list — [commits](https://github.com/pump-fun/pump-public-docs/commits/main); [FEE_RECIPIENTS.md](https://github.com/pump-fun/pump-public-docs/blob/main/docs/FEE_RECIPIENTS.md)
- 2026-01-09: creator fee sharing. `create_fee_sharing_config` rewrites `bonding_curve.creator` (and `pool.coin_creator`) to the `sharing_config` PDA, so the `creator_vault` derivation changes for that coin — [CREATOR_FEE_SHARING.md](https://github.com/pump-fun/pump-public-docs/blob/main/docs/instructions/CREATOR_FEE_SHARING.md)

## 2. Bonding-curve math: reserves, buy/sell formulas, fees, rounding, slippage, completion, progress

### Takeaway
It is a virtual-reserve constant product (x·y=k) over `virtual_quote_reserves` / `virtual_token_reserves`. Fees today are a flat **1.25% (0.95% protocol + 0.30% creator)**, each **rounded up (ceil)**. The **buyback fee is half of the protocol fee, not an extra charge**. All formulas below reproduced real mainnet trades to the lamport. Always price from the live curve account: mayhem coins use non-standard virtual SOL and 2B supply.

### Cited Findings
- Live `Global` initial parameters (2026-10-03): `initial_virtual_token_reserves = 1,073,000,000,000,000`, `initial_virtual_sol_reserves = 30,000,000,000` (30 SOL), `initial_real_token_reserves = 793,100,000,000,000`, `token_total_supply = 1,000,000,000,000,000` (1B tokens at 6 decimals), `initial_virtual_quote_reserves = 4,292,000,000` (USDC base units, used to seed USDC curves), `pool_migration_fee = 15,000,001`, `fee_basis_points = 95`, `creator_fee_basis_points = 5` (fallback only) — [Global on Solscan](https://solscan.io/account/4wTV1YmiEkRvAtNtsSGPtUrqRYQMe5SKy2uB4Jjaxnjf) (decoded via SDK on 2026-10-03); the same initial reserves are shown in [PUMP_PROGRAM_README](https://github.com/pump-fun/pump-public-docs/blob/main/docs/PUMP_PROGRAM_README.md)
- Live pump `FeeConfig` (`8Wf5TiAh…`): a single fee tier, threshold 0 → `lp 0 / protocol 95 / creator 30 bps`. `stable_fee_tiers` (USDC) are identical, and `flat_fees` / `exotic_flat_fees` = 0/95/30 — [pump FeeConfig on Solscan](https://solscan.io/account/8Wf5TiAheLUqBrKXeYg2JtAFFMWtKdG2BSFgqUcPVwTt) (decoded 2026-10-03). - Fee-tier selection: `market_cap = virtual_quote_reserves * mint_supply / virtual_token_reserves`. Use the first tier if mcap is below the first threshold; otherwise use the highest tier whose `market_cap_lamports_threshold <= mcap`. For curves the SDK uses a fixed 1e15 supply for non-mayhem coins and the real mint supply for mayhem coins. Schedule by quote mint: SOL-like (default key, wSOL, Token-2022 native mint) → `fee_tiers`; USDC → `stable_fee_tiers`; others → `exotic_flat_fees` (or `flat_fees` if unset). - Fee rounding is `fee = ceil(amount * bps / 10_000)`, computed separately for protocol and creator. The creator fee is charged only if `bonding_curve.creator != Pubkey::default()` (or the curve is new) — [pump-sdk src/fees.ts](https://www.npmjs.com/package/@pump-fun/pump-sdk?activeTab=code)
- SDK quote functions (no slippage applied): `getBuySolAmountFromTokenAmountQuote = amount*vQ/(vT-amount) + 1`; `getBuyTokenAmountFromSolAmountQuote = in*vT/(vQ+in)` with `in = (amount-1)*10000/(10000+totalBps)`; `getSellSolAmountFromTokenAmountQuote = amount*vQ/(vT+amount)`. Buys are capped at `real_token_reserves`. A curve with `virtual_token_reserves == 0` is treated as migrated and returns 0 — [pump-sdk src/bondingCurve.ts](https://www.npmjs.com/package/@pump-fun/pump-sdk?activeTab=code)

### Inferences
- **Bonding progress %**: there is no official formula. The natural derivation from the documented completion condition is `progress = (initial_real_token_reserves − real_token_reserves) / initial_real_token_reserves`, with `initial_real_token_reserves = 793.1e12` for standard coins. Example: real_token_reserves 396,834,797,138,694 gives about 49.96%. Equivalently, it is the token-side virtual minus real offset (279.9e12), which held on mayhem coins too. Do not compute progress from SOL raised, because mayhem curves have different virtual SOL.
- Because there is only one fee tier on curves today, market-cap tiering is moot pre-migration. Still, implement the tier lookup, since the docs say a correct implementation survives future tier changes.
- A conservative builder for `buy` should send `max_sol_cost = ceilFee(cost) * (1 + slippage)` and handle `6002 TooMuchSolRequired`. For "spend X SOL", use `buy_exact_sol_in` / `buy_exact_quote_in_v2` with `min_tokens_out` derived from the `(net-1)` formula.

- No official worked numeric examples exist in the pump repo; the examples above are mine, built from on-chain-verified formulas.
- Mayhem-mode virtual parameter rules and the 2B supply mechanics are not documented in the public repo.

## 3. Graduation: when and how a coin migrates to PumpSwap, liquidity, detection, post-migration fees

### Takeaway
When the last real token is bought (`complete = true`, `real_token_reserves = 0`), anyone can call the idempotent `migrate`. It creates the **canonical PumpSwap pool** at PDA `["pool", u16 0, pool_authority, mint, wSOL]`, seeds it with the curve's SOL (minus a 0.015 SOL migration fee) and remaining tokens, and burns the LP. Detect it via `CompleteEvent` / `CompletePumpAmmMigrationEvent` or the pool account appearing. Post-migration fees follow the canonical-pool market-cap tiers (1.25% below ~420 SOL mcap, falling to 0.30% at 98,240+ SOL).

### Cited Findings
- `migrate(user, mint)` is permissionless and idempotent. It requires `complete == true && real_token_reserves == 0`. `pool_migration_fee` (15,000,001 lamports) covers the accounts created (max `MAX_MIGRATE_FEES = 15_000_000`). LP tokens received are burnt — [PUMP_PROGRAM_README](https://github.com/pump-fun/pump-public-docs/blob/main/docs/PUMP_PROGRAM_README.md)
- `migrate` accounts and seeds: `pool` = `["pool", [0,0] (u16 index 0 LE), pool_authority, mint, wsol_mint]` under pump_amm; `pool_authority` = `["pool-authority", mint]` under pump; `lp_mint` = `["pool_lp_mint", pool]` under pump_amm; `amm_global_config` = `["global_config"]` under pump_amm; pool vaults are ATAs of `pool`. `migrate_v2` is the non-SOL-quote version (`quote_mint`, `quote_token_program`) — [idl/pump.json](https://github.com/pump-fun/pump-public-docs/blob/main/idl/pump.json); `CANONICAL_POOL_INDEX = 0` and `canonicalPumpPoolPda(mint)` — [pump-sdk src/pda.ts](https://www.npmjs.com/package/@pump-fun/pump-sdk?activeTab=code)

## 4. PumpSwap (pump AMM): program, IDL, buy/sell accounts, pool PDA, fees, coin-creator vault, effective reserves

### Takeaway

- Indexers and quoters must store `virtual_quote_reserves` as signed and add it on every quote. Charting the "price" from vault balances alone is also wrong for boost pools.

## 6. Aggregators for the long tail: Jupiter (Ultra vs Metis/Swap API V2, lite-api, fees, latency) and alternatives

### Takeaway
Jupiter consolidated everything into **Swap API V2** at `https://api.jup.ag/swap/v2`. There are two paths. The **Meta-Aggregator** (`/order` + `/execute`; Metis, JupiterZ RFQ, DFlow and OKX compete) **charges a Jupiter platform fee** of 0–50 bps, and **50 bps on tokens under 24h old**. The **Router** (`/build`, Metis only, raw instructions) **charges no Jupiter swap fee**, and `platformFeeBps` defaults to 0. A zero-fee memecoin terminal should use direct instructions first and Jupiter `/build` as the long-tail fallback. DFlow's `/order` (no protocol fee) is a credible second aggregator.

### Cited Findings
- Swap API V2 paths: Meta-Aggregator (`GET /swap/v2/order` + `POST /swap/v2/execute`, assembled tx, managed landing, all routers, "Swap fees: Yes (Jupiter platform fee)", integrator fees via referral) versus Router (`GET /swap/v2/build`, raw instructions, Metis only, "Swap fees: No", integrator fee via `platformFeeBps`, full transaction control, land via your RPC or `tx.jup.ag`). JupiterZ RFQ is unavailable on `/build`, and RFQ transactions cannot be modified — [Jupiter: Solana Swap API](https://developers.jup.ag/docs/swap/index.md)
- Ultra migration: "Base URL: `https://ultra-api.jup.ag`" becomes `https://api.jup.ag/swap/v2`, with identical `/order` + `/execute` params — [Jupiter: Ultra to Meta-Aggregator](https://developers.jup.ag/docs/swap/migration/ultra-to-order.md). Metis Swap API V1 (`/quote` + `/swap-instructions`) migrates to `/build` — [Jupiter docs index](https://developers.jup.ag/docs/llms.txt)
- Jupiter platform fee on `/order` by pair: buying Jupiter tokens 0; pegged (LST-LST, stable-stable) 0; SOL-stable 2 bps; LST-stable 5; everything else 10; **new tokens (within 24h of token age) 50 bps**. The fee mint priority is SOL > stables > LSTs > bluechips > others. Referral fees are 50–255 bps, with Jupiter taking 20% of the integrator fee — [Jupiter: Swap fees](https://developers.jup.ag/docs/swap/fees.md)
- `/build`: "Jupiter does not charge swap fees on `/build`." `platformFeeBps` defaults to `0` and requires a `feeAccount` (any SPL token account you control). Other params include `maxAccounts` (1–64, default 64), `dexes` / `excludeDexes` (labels from program-id-to-label), `payer`, `forJitoBundle`, and `mode=fast` to cut latency — [Jupiter: Build](https://developers.jup.ag/docs/swap/build/index.md); [Jupiter docs index](https://developers.jup.ag/docs/llms.txt)
- Auth and limits: keyless access at 0.5 RPS on `api.jup.ag`; Free key 1 RPS; Developer $25/mo 10 RPS; Launch $100/mo 50 RPS; Pro $500/mo 150 RPS; 60-second sliding window. `/execute` has its own bucket (20/50/100 RPS) — [Jupiter: Rate limits](https://developers.jup.ag/docs/portal/rate-limits.md); [Jupiter docs index](https://developers.jup.ag/docs/llms.txt). The Swap API page says "All endpoints require an API key via the `x-api-key` header", while the index advertises keyless 0.5 RPS (minor docs inconsistency) — [Jupiter: Swap API](https://developers.jup.ag/docs/swap/index.md)
- Latency: the API gateway runs in 6 AWS regions (ap-southeast-1, eu-central-1, us-east-1, sa-east-1, ap-northeast-1, us-west-2), and Jupiter recommends colocating in the same region. This "applies to all Jupiter API products accessed via api.jup.ag and lite-api.jup.ag" — [Jupiter: Latency](https://developers.jup.ag/docs/portal/latency.md); [docs index](https://developers.jup.ag/docs/llms.txt). `lite-api.jup.ag/swap/v1/program-id-to-label` still responded on 2026-10-03 ([lite-api labels](https://lite-api.jup.ag/swap/v1/program-id-to-label))
- Jupiter routes the memecoin venues directly (Pump.fun curve, PumpSwap, LaunchLab, DBC, Boop.fun, Heaven, Moonit, MemeFun, Trends …) — [program-id-to-label](https://api.jup.ag/swap/v1/program-id-to-label)
- DFlow: "DFlow charges **no protocol fee** on spot trades". `/order` returns a fully constructed transaction that can be bundled with your own instructions. There are imperative `/quote`, `/swap`, `/swap-instructions` and declarative `/intent` / `/submit-intent` endpoints, WebSocket quote and book streams, and API keys for production — [DFlow: Spot Trading](https://pond.dflow.net/spot/introduction.md); [DFlow docs index](https://pond.dflow.net/llms.txt)
- OKX's DEX API documents "Get Solana Swap Instructions" and "Advanced Control With Swap-Instructions on Solana" pages (the page body returned 403 to my fetch) — [OKX docs index](https://web3.okx.com/llms.txt)

### Inferences
- Build direct for pump curve, PumpSwap, LaunchLab (+CPMM) and later DBC/DAMM v2. These are the hot paths where an aggregator adds ~100–300 ms of HTTP RTT, rate-limit risk, and (on `/order`) a 50 bps new-token fee. Use Jupiter `/build` (fee 0) for long-tail venues and as a "best route" sanity check, and DFlow `/order` as a fallback/secondary quote. Avoid `/order` in a zero-fee product unless the user opts in.
- `/build` cannot be used for RFQ, but RFQ rarely matters for fresh memecoins.

## 7. Token-2022, wSOL, ATAs, rent, and closing accounts

### Takeaway
pump `create_v2` coins are Token-2022 with only metadata extensions (**no transfer fee, no transfer hook**). Their ATAs are 170 bytes. The bonding curve settles in native SOL, while PumpSwap uses wSOL ATAs. **Mainnet rent is now lower than the classic constants** (165-byte token account = 1,488,440 lamports, not 2,039,280), so never hardcode rent. Meteora DBC supports transfer-hook Token-2022 pools, which need extra remaining accounts.

### Cited Findings
- `create_v2` creates a Token-2022 mint (`TokenzQdBNbLqP5VEhdkAS6EPFLC1PHnBqCXEpPxuEb`), `decimals = 6`, with a metadata pointer set to the mint itself. Legacy `create` uses SPL Token (`TokenkegQfeZyiNwAJbNbGKPFXCWuBvf9Ss623VQ5DA`) plus Metaplex metadata — [COIN_CREATION.md](https://github.com/pump-fun/pump-public-docs/blob/main/docs/instructions/COIN_CREATION.md); [idl/pump.json](https://github.com/pump-fun/pump-public-docs/blob/main/idl/pump.json)
- On-chain check (2026-10-03): `create_v2` mints have extensions `["metadataPointer","tokenMetadata"]` only, mint and freeze authority `null`, and supply 1e15 (normal) or 2e15 (mayhem). The curve's Token-2022 ATA is 170 bytes with `["immutableOwner"]` — [mint 3Z16oesT…](https://solscan.io/token/3Z16oesTxW8exoENZTCd1ADVzFPePH3n33cTkUDLpump), [mint 2rGcJhhe…](https://solscan.io/token/2rGcJhheGSAYN84ksPh7keV4QgnD92aqHUKZJ2w3pump)
- Pass the base mint's token program as `base_token_program` and wSOL + SPL Token as quote for SOL coins. The legacy-coin example passes `TOKEN_PROGRAM_ID` for both — [BUY.md](https://github.com/pump-fun/pump-public-docs/blob/main/docs/instructions/BUY.md)
- The bonding curve moves native SOL; PumpSwap uses wSOL; pump-swap-sdk wraps around buys/sells (`withWsolAccount`) and adds `createAssociatedTokenAccountIdempotentInstruction` for missing user ATAs — [pump-swap-sdk src/sdk/offlinePumpAmm.ts](https://www.npmjs.com/package/@pump-fun/pump-swap-sdk?activeTab=code); [PUMP_CASHBACK_README](https://github.com/pump-fun/pump-public-docs/blob/main/docs/PUMP_CASHBACK_README.md). The PumpSwap `claim_cashback` expects the user's wSOL ATA to exist ("use 'create idempotent associated token account'") — [PUMP_CASHBACK_README](https://github.com/pump-fun/pump-public-docs/blob/main/docs/PUMP_CASHBACK_README.md)
- Mainnet `getMinimumBalanceForRentExemption` on 2026-10-03: 82 B (mint) = 1,066,800; **165 B (SPL token account) = 1,488,440**; **170 B (Token-2022 ATA) = 1,513,840**; 137 B (user_volume_accumulator) = 1,346,200; 151 B = 1,417,320; 301 B = 2,179,320 lamports. That is 5,080 lamports per byte including the 128-byte overhead — [Solana RPC getMinimumBalanceForRentExemption](https://solana.com/docs/rpc/http/getminimumbalanceforrentexemption) (queried on api.mainnet-beta.solana.com, apiVersion 4.3.0)
- **Conflict:** pump's BUY.md still quotes "Rent for 137-byte account if missing: 0.0018444 SOL", which corresponds to the old rate. The live value is 0.0013462 SOL — [BUY.md](https://github.com/pump-fun/pump-public-docs/blob/main/docs/instructions/BUY.md) vs RPC above
- DBC: Token-2022 support, transfer-hook pools (`swap2_with_transfer_hook`), quote-mint token badges and transfer-fee rules — [Meteora docs index](https://docs.meteora.ag/llms.txt); [DBC changelog](https://docs.meteora.ag/developer-guides/dbc/changelog.md)
- Jupiter `/build` docs include a "Common Instructions" reference (ATA creation with idempotent create, etc.) to compose around swap instructions — [Jupiter docs index](https://developers.jup.ag/docs/llms.txt)

### Inferences
- Detect the token program by reading the mint account's owner (never by mint suffix). Derive ATAs with the matching program ID. Use idempotent ATA creation in the same transaction. For sells to zero, append a `CloseAccount` to reclaim about 0.0015 SOL (Token-2022 accounts can be closed only at zero balance).
- For DBC transfer-hook pools, either implement hook account resolution or route via aggregator. pump coins currently need no hook handling.

### Gaps
- I did not find the SIMD or changelog explaining the lower rent rate (only the live RPC values).
- I did not verify Token-2022 close-account edge cases (withheld transfer fees) against a source.

## 8. Client libraries in 2026: web3.js v1 vs @solana/kit; official and community pump SDKs

### Takeaway
`@solana/web3.js` 1.x is on a **maintenance branch** (latest 1.99.0, 2026-09-08) whose README points to **`@solana/kit`** (8.4.0, 2026-09-28) as the successor. However, **every official launchpad/DEX SDK, including `@pump-fun/pump-sdk` 2.0.0 and `@pump-fun/pump-swap-sdk` 1.20.0, is still web3.js v1 + Anchor 0.31**. A Kit-native terminal therefore needs its own IDL-driven instruction encoders (with the official SDKs as test oracles) or a web3.js-v1 island bridged via `@solana/compat`.

### Cited Findings

## 9. Implications for the build

### Takeaway
**Phase 1 (direct, local builders):** pump.fun curve (`buy_v2` / `sell_v2` / `buy_exact_quote_in_v2`, with a legacy fallback), PumpSwap (`buy` / `buy_exact_quote_in` / `sell` with remaining accounts and effective reserves), Raydium LaunchLab, and Raydium CPMM. **Phase 2:** Meteora DBC and DAMM v2 (port the official quote math), then Raydium AMM v4/CLMM, Meteora DLMM and Orca if the volume justifies it. **Long tail:** Jupiter `/build` (0 Jupiter fee), with DFlow `/order` as backup. **Library:** `@solana/kit` core with IDL-generated/hand-written encoders; official web3.js-v1 SDKs only in tests/CI as oracles.

### Cited Findings
- Venue concentration supporting this phase split: PumpSwap is the #1 Solana DEX by 30-day volume ($13.41B), the pump curve does $3.26B, and StonkFun (LaunchLab) does $0.80B — [DefiLlama Solana DEX overview](https://api.llama.fi/overview/dexs/solana?excludeTotalDataChart=true&excludeTotalDataChartBreakdown=true). Launchpad revenue: pump.fun 45%, StonkFun (LaunchLab) 38%, BONK.fun+Graphite (LaunchLab) ~12% — [DefiLlama fees overview](https://api.llama.fi/overview/fees?excludeTotalDataChart=true&excludeTotalDataChartBreakdown=true&dataType=dailyRevenue)

- Pump interface changes land with about a week of devnet notice and SDK releases (e.g., 2026-04-22 notice for 2026-04-28) — [BREAKING_FEE_RECIPIENT.md](https://github.com/pump-fun/pump-public-docs/blob/main/docs/BREAKING_FEE_RECIPIENT.md); [commits](https://github.com/pump-fun/pump-public-docs/commits/main)
